# Ember — Cigar Tracker PWA

A privacy-first, offline-capable Progressive Web App for daily cigar tracking.
React + Vite + Tailwind CSS v4. No backend: every record stays in your browser's
`localStorage`.

## Features

**Daily logging**
- Quick `+` / `-` counters for four contexts: Home, University, Out with friends, Driving
- Every log stores an exact timestamp; logging on a past day is supported from the calendar
- Time-of-day insights (morning / afternoon / evening / late night) with peak detection

**Visual heatmap**
- GitHub-style monthly contribution grid with a green → light green → red scale
- The maximum threshold is configurable (3–20); all colours recalculate relative to it

**Full calendar**
- Navigate any month, select any day, and see the per-location + time-of-day breakdown
- Month totals and month-over-month change

**Insights**
- Monthly total, daily average, active days
- Location frequency bars and time-of-day chart

**PWA**
- Installable on desktop and mobile (`manifest.webmanifest` + service worker)
- App shell, icons and Google Fonts are cached for offline use
- Works after the first visit with no network

**Data**
- Export / import a JSON backup
- Everything is local — nothing is ever uploaded

## Getting started

```bash
npm install
npm run dev        # dev server
npm run build      # type-check + production build into dist/
npm run preview    # serve the production build
```

## Project structure

```
├── index.html
├── public/
│   ├── manifest.webmanifest   # PWA manifest
│   ├── sw.js                  # service worker (offline app shell)
│   └── icons/                 # generated PNG icons + favicon.svg
├── scripts/
│   └── generate-icons.mjs     # dependency-free icon generator (npm run icons)
├── src/
│   ├── App.tsx                # all UI (dashboard, calendar, insights, settings)
│   ├── main.tsx               # entry + service-worker registration (prod only)
│   └── index.css              # Tailwind v4 theme + component layer
├── vite.config.ts
└── tsconfig.json
```

## Storage model

| Key                | Contents                                              |
|--------------------|-------------------------------------------------------|
| `ember-events`     | `{ "YYYY-MM-DD": SmokeEvent[] }` — id, context, timestamp |
| `ember-threshold`  | heatmap maximum threshold                             |

## Icons

All four PNGs are generated by `scripts/generate-icons.mjs` (pure Node, no
dependencies). Regenerate them with:

```bash
npm run icons
```

## Deploying

`vite.config.ts` uses a relative `base`, and the manifest / service-worker URLs
are relative too, so the build works from a domain root **and** from a
sub-path such as `https://<user>.github.io/<repo>/` with no extra config.

- Serve the contents of `dist/` from your host.
- The service worker must be reachable at `./sw.js` (it is, since `public/` is
  copied verbatim into `dist/`).
- Bump `VERSION` in `public/sw.js` on each release so returning visitors pick
  up the new assets.
- HTTPS is required for the service worker (localhost is exempt).

## Not implemented yet

These were listed as optional in the original spec and are not part of the

ratings, CSV export (JSON export exists), and spend tracking.
